# Security model and review notes

## Authentication and authorization
Sanctum uses Laravel's `web` guard for first-party session cookies. Browser API routes explicitly use the web middleware stack, including CSRF. Only the Razorpay webhook is stateless/CSRF-exempt and requires raw-body HMAC authentication. HttpOnly session cookies, session encryption, login session regeneration and logout invalidation are enabled. Production must use Secure cookies and HTTPS. CORS allows explicit FRONTEND_URL origins with credentials, never wildcard origins. Rate limits apply to login, registration, page requests, checkout, verification and downloads. Add edge WAF and per-account/IP abuse review before launch. No bearer tokens are issued by this application.

Admin middleware guards every admin endpoint; the Book policy also protects modifications/reader/download permissions. Registration ignores roles. Role changes cannot demote the current administrator. Promotion requires a deliberate CLI action on an existing account. MFA, email verification and password-reset mail flows are future hardening work and not represented as implemented.

## Files and rights
Uploads validate MIME, size and PDF signature; covers reject SVG. Names and paths are generated server-side. User-supplied paths are never used for storage lookup. Published titles require affirmative rights confirmation and evidence; actor/time are stored. Original files and raster/text pages remain in a private disk; local auto-serving is disabled. Do not run `storage:link` on the private disk. Bucket ACLs and CDN origins must remain private; a signed application URL does not replace server-side authorization.

Poppler is native code parsing untrusted inputs: keep it patched and run the queue as a non-root user with CPU/memory/PID limits and a process timeout. Inputs are at most 50 MB / 1,000 pages. Reject encrypted PDFs. Rendering jobs use argument arrays, not shell interpolation. Per-version SHA paths avoid mixed page versions; stale jobs cannot mark replacement PDFs ready. Render workers should use a hardened dedicated sandbox with no unnecessary network/secrets in production, virus scanning/quarantine and storage quotas. Old rendered versions need a retention cleanup job; deleting files while readers are active must be coordinated. There is no malware scanner in this repository.

Reader images and extracted text require authentication, publication rights, read availability, an expiring relative URL signature and matching account/session. The response is private/no-store. Original downloads additionally require a captured-payment entitlement and current download availability; each is logged with an HMAC of the IP. This protects URLs and casual extraction, not the displayed content. Text extraction supports screen readers where PDFs contain text; scanned PDFs require OCR/editorial work. Test keyboard navigation, contrast and representative Hindi/English PDFs with assistive technology.

## Payments
Amounts are integer paise from books, snapshotted in orders; frontend amounts are ignored. Checkout signatures use server-stored gateway order IDs. A signature alone is insufficient: Laravel fetches provider payment details and checks order, captured status, exact amount and INR. The shared capture service runs under row locks; payment IDs, entitlement ownership and webhook IDs are unique. Webhooks use a separate secret, raw request bytes and event-ID payload collision checks. Failed transactions roll back event processing and permit retries. Capture events after a refund cannot restore access. A refund before capture processing retries until its capture/order is available. Monitor dead-letter/HTTP errors and reconcile in Razorpay.

Do not log raw webhook bodies, credentials or payment instrument data. Payment audit rows intentionally retain order IDs after account/book retirement. Implement legally reviewed retention/anonymization procedures before offering account deletion. The current UI does not offer account deletion.

## Launch review
Review threat model, role administration, public forms, file quotas, dependency advisories, gateway capture/refund policies, legal text and data retention. Secure production ingress with CSP, TLS, HSTS, private DB access and appropriate trusted proxy configuration. Never set trusted proxies to all networks without an ingress boundary. Secrets belong in a secret manager; rotate APP_KEY only with a session/data migration plan. Use separate test/live Razorpay keys and separate webhook secrets.
